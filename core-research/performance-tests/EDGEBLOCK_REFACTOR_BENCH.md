## 一、数据加载性能

**旧架构**：HashMap 构建 → to_csr() → from_csr→EdgeBlock（三步转换）  
**新架构**：EdgeBlock 原生构建（一步到位）

| 规模 | 旧: HashMap | 旧: to_csr() | 旧: →EdgeBlock | 旧: 总计 | 新: EdgeBlock | 节省 |
|------|-----------|-------------|---------------|----------|--------------|------|
| 1K/10K | 1.91ms | 2.62ms | 0.22ms | **4.74ms** | **0.79ms** | **3.95ms (83%)** |
| 10K/100K | 15.28ms | 23.98ms | 1.67ms | **40.93ms** | **8.14ms** | **32.79ms (80%)** |
| 100K/1M | 411.81ms | 311.24ms | 22.48ms | **745.53ms** | **293.20ms** | **452.33ms (61%)** |

**结论**：新架构消除了 HashMap→CSR→EdgeBlock 的三步转换链，数据加载耗时减少 61%~83%。100K/1M 规模下直接节省 452ms。

## 二、GPU PageRank

### 2.1 单次迭代性能（100 轮平均）

| 规模 | CPU f64（基准）| GPU CSR full PR | GPU EdgeBlock (冷) | GPU EdgeBlock (缓存) |
|------|:---:|:---:|:---:|:---:|
| 1K/10K | 0.02ms | 0.84ms | 0.66ms | 0.66ms |
| 10K/100K | 0.14ms | 0.93ms | 1.14ms | **0.85ms** |
| 100K/1M | 4.73ms | 5.15ms | 7.90ms | **6.04ms** |

> **冷启动**：首次调用，需要分配 GPU buffer。**缓存复用**：后续调用，buffer 预分配并增量更新。

**关键发现**：
- ✅ GPU 缓存版本在 10K 规模下比 CSR 版本略快（0.85ms vs 0.93ms）
- ⚠️ 100K 规模下 EdgeBlock 稍慢（6.04ms vs 5.15ms），因为 EdgeBlock kernel 读取格式比 CSR 多一次间接寻址
- ✅ 所有 GPU 版本 PR 值精度一致（Δ < 2.3e-6），排名结果正确

### 2.2 端到端耗时（构建 + 单次迭代）

**结论**：端到端加速 2.5x ~ 4.7x。主要收益来自消除 CSR 转换（占总耗时的 40%~50%）。

## 五、分析

### 5.1 为什么端到端加速显著？

旧架构的算法执行流程需要三步转换：
```
HashMap 构建 → to_csr() 全量重建 → from_csr→EdgeBlock → GPU 执行
   411ms         311ms               22ms              6ms
                            745ms 总计
```

新架构一步到位：
```
EdgeBlock 构建 → GPU 执行
   293ms           6ms
           299ms 总计
```

**关键**：`to_csr()` 的 311ms（100K 规模）在每次数据加载后都要付一次。EdgeBlock 原生格式消除了这个中间步骤。

### 5.2 GPU 计算时间对比

对于 GPU kernel 执行本身，EdgeBlock 和 CSR 格式的性能接近：
- 小图（1K）：EdgeBlock 更快（0.66ms vs 0.84ms），因为 kernel overhead 小
- 大图（100K）：CSR 略快（5.15ms vs 6.04ms），因为 CSR format 内存访问更紧凑

差值在 1~2ms 范围内，对端到端耗时影响远小于构建阶段的 452ms 节省。

### 5.3 GPU Buffer 缓存效果

| 规模 | 冷启动 | 缓存复用 | 节省 |
|------|--------|---------|------|
| 1K/10K | 0.66ms | 0.66ms | 0% (buffer 太小) |
| 10K/100K | 1.14ms | 0.85ms | **25%** |
| 100K/1M | 7.90ms | 6.04ms | **24%** |

缓存对大图的效果更明显（buffer 越大，分配和拷贝成本越高）。

### 5.4 精度验证

所有 GPU 版本（CSR full PR、EdgeBlock 冷/缓存）的 PR 值之和误差一致（Δ ≈ 2.3e-6），源自 f32 + Kahan 求和精度。排名结果正确无误。

## 六、结论

1. ✅ **端到端加速 2.4x ~ 4.7x**：三种规模、两种算法，一致提升
2. ✅ **数据加载节省 61%~83%**：消除 HashMap→CSR→EdgeBlock 三步转换
3. ✅ **GPU PageRank 缓存有效**：buffer 复用节省 24%~25%（大图）
4. ✅ **精度一致**：新旧架构 PR 值误差相同（f32 精度，Δ ≈ 2.3e-6）
5. ⚠️ **GPU kernel 执行时间**：EdgeBlock 和 CSR 性能接近（±1~2ms），核心收益在构建阶段

**整体判断**：EdgeBlock 统一内存重构在性能层面是成功的。消除了 HashMap→CSR 的中间格式瓶颈，让图数据库的原生存储格式与 GPU 计算格式完全统一，实现了「一次构建，零转换」的设计目标。
