# 增量算法性能验证报告

**日期**：2026-07-07  
**测试**：全量重算 vs 增量更新（新增 50 条边后）  
**目标**：来自 PROJECT_PRINCIPLES.md

---

## 测试方法

1. 构建随机图（1K/10K/50K 顶点）
2. 运行全量算法 → 记录耗时
3. 新增 50 条边 → 确定受影响顶点
4. 运行增量算法（只处理受影响顶点）→ 记录耗时
5. 计算加速比 = 全量耗时 / 增量耗时

---

## 结果

### PageRank（目标：244x）

| 规模 | 全量PR | 增量PR | 加速比 | 达目标？ |
|------|--------|--------|--------|:---:|
| 1K / 5K | 0.55ms | 6.41ms | **0.1x** | ❌ |
| 10K / 50K | 6.13ms | 0.82ms | **7.5x** | ❌ |
| 50K / 250K | 59.85ms | 3.17ms | **18.9x** | ❌ |

**分析**：
- 1K 图太小，GPU kernel 启动开销（Metal command buffer + pipeline + dispatch）远超计算本身
- 50K 下 18.9x 已是有效加速，但距 244x 仍有差距
- 244x 目标来自 Swift 原型的「10 轮全量 GPU PR vs 1 轮增量 GPU PR」，且图变化极小（仅 1 条边）
- 当前测试新增 50 条边 = 更多受影响顶点 = 更多 GPU 工作量

### BFS（目标：80x）

| 规模 | 全量BFS | 增量BFS | 加速比 | 达目标？ |
|------|---------|---------|--------|:---:|
| 1K / 5K | 0.03ms | 0.001ms | 31.2x | ❌ |
| 10K / 50K | 0.38ms | 0.001ms | **283x** | ✅ |
| 50K / 250K | 1.91ms | 0.001ms | **1580x** | ✅ |

**分析**：
- 增量 BFS 只检查新增边的源顶点，O(新增边数) = O(50)，与全量 BFS 的 O(V+E) 形成鲜明对比
- 图越大，加速比越显著

### Connected Components（目标：74x）

| 规模 | 全量CC | 增量CC | 加速比 | 达目标？ |
|------|--------|--------|--------|:---:|
| 1K / 5K | 0.11ms | 0.001ms | 87.7x | ✅ |
| 10K / 50K | 1.20ms | 0.002ms | **720x** | ✅ |
| 50K / 250K | 7.38ms | 0.002ms | **4920x** | ✅ |

**分析**：
- Union-Find 的增量更新只需合并新增边连接的集合，O(新增边数 × α(n))
- 加速比随规模线性增长

---

## 汇总

| 算法 | 目标 | 实际(50K) | 状态 |
|------|:---:|:---:|:---:|
| 增量 PageRank | 244x | **18.9x** | ⚠️ 差距较大 |
| 增量 BFS | 80x | **1580x** | ✅ 远超 |
| 增量 CC | 74x | **4920x** | ✅ 远超 |

---

## 结论

1. ✅ **BFS 和 CC 的增量算法已达标**，且远超预期——图越大优势越明显
2. ⚠️ **PageRank 未达标**（18.9x vs 244x），需优化
3. **PageRank 差距原因分析**：
   - GPU kernel 启动开销在小图上占主导（1K 下 0.1x）
   - 增量 kernel 使用 EdgeBlock 格式需要额外内存访问（block header 读取）
   - 244x 的原始对比场景是极端情况（1 条边 vs 全量 10 轮迭代）
   - 当前测试的 50 条边产生更多受影响顶点，增量工作本身更大

---

## 优化建议

1. **减少 GPU kernel 调用开销**：用 EdgeBlockCache 缓存 buffer（已实现），避免首次调用的大开销
2. **批量增量更新**：如果一次有多个边变更，合并受影响顶点后再一次 GPU 调用
3. **小图回退 CPU**：<1K 顶点时直接用 CPU 做增量，避免 GPU 开销
4. **边属性支持后重测**：当前增量 PR 用的是 `from_csr` 构建的 EdgeBlock（旧 API），更新到新 API 后可能改善
